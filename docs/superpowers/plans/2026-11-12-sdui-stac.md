## Decisões de mecânica (o "como")

1. **Features e módulos:** feature `sdui_stac_1 = ["dep:serde", "dep:serde_json"]` (sem umbrella, sem dependência de outra feature; ninguém a puxa). Módulos: `sduix` (guarda-chuva, `#[cfg(any(feature = "sdui_stac_1"))]` em `lib.rs`, ampliado a cada major/engine) > `sduix::stacx` (`#[cfg(any(feature = "sdui_stac_1"))]`) > `sduix::stacx::v1` (`#[cfg(feature = "sdui_stac_1")]`). Majors futuros: `sdui_stac_2` -> `stacx::v2`, só acrescentando linhas no `cfg(any(...))` e um diretório novo; nada existente muda. Convenção `sdui_stac_<major>` / `stacx::v<major>`.
2. **Código comum (`sduix::stacx::common`, sempre compilado com qualquer feature Stac, genérico e independente de major):** `Slot<W>`/`Many<W>`/`Named<W>` (aninhamento genérico: filho único opcional, lista, filhos nomeados, sempre `Box` onde há recursão), trait `StacNode` (`const KIND`, `fn type_name()`), valor dinâmico `Dyn<T>` (`Literal(T)` | `Ref(StateRef)`; `StateRef` serializa para o template de referência que o Stac usa — **confirmar a sintaxe exata no código/docs do Stac v1.6.0 na T3**, ex.: `{{chave}}`), `ValidationIssue` + trait `Validate` (árvore inválida segundo o Stac é acusada, ver decisão 5), helper de serialização com `skip_serializing_if = "Option::is_none"`.
3. **Tipos por major (`stacx::v1`):** `enum Widget` e `enum Action` fechados (`#[serde(tag = "type")]` para widget; discriminador de action conforme o código do Stac, `actionType`/`type`), um struct por componente em arquivo próprio espelhando o diretório do Stac (`v1/widgets/column.rs`, `v1/actions/navigate.rs`, `v1/foundation/<grupo>/...`, `v1/theme/...`). Só `Serialize` (+ `Debug`, `Clone`, `PartialEq`) — o backend produz telas, não lê. Campos opcionais = `Option<T>` omitidos quando `None` (reflete "o que o Stac assume quando omitido"; nunca emitir default por conta própria). Nomes de campo e valores de enum seguem exatamente o JSON do código-fonte Dart (`.g.dart` e `toJson`), via `#[serde(rename...)]` explícito quando divergir de camelCase. `double` converter do Stac: números sempre `f64` serializados como número JSON.
4. **Builders/DSL:** para cada struct, `Type::new(<campos obrigatórios>)` + métodos encadeados `.campo(valor)` (consumindo `self`), e funções-atalho em `v1::dsl` (`column()`, `text("..")`, `navigate(..)`) reexportadas em `v1::prelude`. Nenhuma dependência nova de builder; um `macro_rules!` interno (`stac_struct!`) em `common` gera struct + setters + `Serialize` para reduzir boilerplate de centenas de tipos (definido e validado na T3).
5. **Validação de árvore:** `Validate::validate(&self) -> Vec<ValidationIssue>` verifica restrições de filhos que o Stac impõe (levantadas na T3 a partir do código; ex.: filhos obrigatórios, tipos permitidos). `SduiResponse` valida antes de serializar; issue -> erro via `DerustError` (500) — nunca resposta parcial/pânico.
6. **Versão consultável:** `v1::STAC_VERSION: &str = "1.6.0"` e `v1::STAC_TAG_COMMIT: &str = "<sha>"`; `stacx::versions()` -> lista das versões habilitadas (`&[("v1","1.6.0")]` conforme `cfg`).
7. **Inventário:** `crates/derust/src/sduix/stacx/v1/inventory.json` (commitado), gerado por script `tools/stac-inventory/generate.py` (Python 3 stdlib, sem dependência de Rust) a partir de `packages/stac_core/lib` na tag. Campos por item: `name`, `category` (`widget|action|foundation|theme`), `dart_path`, `json_type` (valor do discriminador, ou `null`), `status` (`supported|partial|unsupported`), `batch` (tarefa responsável), `fixture` (caminho do fixture). Inventário aceito como lista também para majors futuros (`v2/inventory.json`).
8. **Fixtures:** `crates/derust/tests/sdui_stac_v1/fixtures/<categoria>/<nome>.json`; o teste Rust (`#[cfg(feature = "sdui_stac_1")]`) constrói cada componente com os builders, serializa e compara com o fixture (`serde_json::Value` igual). Teste de completude: todo item do inventário com status `supported|partial` tem fixture e teste; falha caso contrário. Fixtures são consumidas pelo harness Dart.
9. **Harness Dart/Flutter:** `tools/stac-compat/v1/` (projeto Flutter com `pubspec.yaml` fixando `stac` na tag `v1.6.0` via `git: {url: https://github.com/StacDev/stac, ref: v1.6.0, path: packages/stac}`), teste `flutter test` que lê todos os fixtures de `crates/derust/tests/sdui_stac_v1/fixtures` e faz o parse real pelo Stac (registro de parsers do Stac -> `Stac.fromJson`/parser equivalente, dentro de `testWidgets` se exigir `BuildContext`; confirmar o ponto de entrada exato na T4). Falha se qualquer fixture não parsear. Um diretório por major (`v2` futuramente) e um job de CI por major. Isolado em `tools/` (fora do pacote publicado: adicionar `exclude` no `Cargo.toml` se necessário para `cargo package`).
10. **CI:** criar `.github/workflows/ci.yml` (hoje inexistente): job `rust` (fmt, clippy `--all-targets` e workspace, nextest com default, `--features sdui_stac_1` e `--all-features`), job `stac-compat-v1` (Flutter via `subosito/flutter-action`, `flutter test` em `tools/stac-compat/v1`). Assim a matriz cresce com um job por major.
11. **`SduiResponse<T>`** em `crates/derust/src/httpx/response/sdui.rs`, `#[cfg(all(feature = "http_server", any(feature = "sdui_stac_1")))]`. Genérico sobre `T: serde::Serialize + Validate + Send + Sync` (serve a qualquer major). Construtor falível `SduiResponse::try_new(status, screen, tags) -> Result<Self, DerustError>` que valida e serializa **uma vez** (corpo `String` guardado), implementa `HttpResponse` (`Content-Type: application/json`, mesmas regras de `x-trace-id` do `JsonResponse`), `with_headers`, e `IntoResponse` em `httpx/axum.rs`. Falha -> `DerustError::without_body(500, "failed to serialize SDUI screen: ..", tags)`. Usa o `content-type` `application/json` (o Stac consome JSON).
12. **Versão da crate:** funcionalidade nova compatível -> bump `0.6.0` -> `0.7.0` na T14 (mesmo padrão do 0.6.0); confirmar com a pessoa na hora do release, não é regra de negócio.
13. **Gate de compilação:** `sduix` independe de `http_server` (usuário que só quer os tipos usa `default-features = false, features = ["sdui_stac_1"]`); só `SduiResponse` exige `http_server`. Verificar `cargo check -p derust --no-default-features --features sdui_stac_1`.

## T3 — Núcleo: tipos base, aninhamento genérico, serialização, valores dinâmicos, validação (dificuldade: complexa) — CONCLUÍDA

Restrições impostas pelo Stac: só os `assert` do `StacBadge` (count>=0, maxCount>0) + números não finitos + referência de estado vazia.
