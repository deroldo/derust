Nada de `rand`, `uuid`, `hex` (jti e sal via `openssl::rand::rand_bytes`; hex/base64url com helpers internos testados).
2. **Feature `cryptox`** = `["dep:josekit","dep:argon2","dep:zeroize","dep:openssl","dep:base64","dep:serde","dep:serde_json","dep:thiserror","dep:async-trait","dep:tokio","dep:tracing"]`. **Nao** liga `http_server`. `cryptox/http.rs` so compila com `#[cfg(feature = "http_server")]`; `SecretsManagerKeySource` so com `#[cfg(feature = "aws")]`. Se `josekit` trouxer `default-features` indesejadas, usar `default-features = false` e confirmar com `cargo tree -e features -i openssl` que continua uma unica `openssl` com `vendored`.
3. **`josekit` isolado:** so os arquivos internos `cryptox/jose.rs` (privado, `pub(crate)`) importam `josekit`. Nenhum tipo do `josekit` aparece na API publica (nem em `Display`/`Debug` de erros). Funcoes internas: `jws_sign_es256(&SigningKey, header_json, payload) -> String`, `jws_verify_es256(&VerifyingKey, token) -> Result<Vec<u8>, _>`, `jwe_encrypt_ecdh_es_a256gcm(&VerifyingKey-like, plaintext)`, `jwe_decrypt(...)`, `jwk_from_public(...)`. Uma troca futura para o plano B fica restrita a esse arquivo.
4. **Validacao propria (issues 59/61/62 do josekit):** o cryptox le e valida header e claims por conta propria *antes e depois* de chamar a primitiva; nunca usa `JwtPayloadValidator`, `decode_with_verifier_selector` nem o leeway do josekit.
5. **Nenhum segredo em claro:** `Debug` de `SigningKey`/`VerifyingKey` mostra so o `kid`; `Debug` de `CodeHasher`, `PasswordHasher`, `JweOpener` e dos `KeySource` e redigido (`***`); PEM e pepper em `Zeroizing`; mensagens de erro (`Display`) sao fixas por variante, **sem** embutir texto de erro de `josekit`/`openssl`/`argon2`, token, PEM, codigo, senha, hash ou caminho de segredo; `tracing` nunca recebe token/PEM/codigo/pepper.
6. **Construtores exigem `iss`/`aud` por parametro (obrigatorios em tempo de compilacao) e recusam vazio em tempo de execucao** com `JwtError::InvalidConfig`. Assinaturas finais (substituem os builders `.issuer()/.audience()` do design):
   - `JwtSignerSettings { issuer: String, audience: String, ttl: Duration }` e `TokenIssuerSettings { issuer, audience, access_ttl, refresh_ttl }`. **Nao ha TTL padrao** (seria regra de negocio nao decidida); TTL zero -> `InvalidConfig`.
   - `JwtSigner::new(SigningKey, TokenType, JwtSignerSettings) -> Result<Self, JwtError>`.
   - `JwtVerifier::new(VerifyingKeySet, TokenType, issuer: impl Into<String>, audience: impl Into<String>) -> Result<Self, JwtError>` (conjunto vazio -> `InvalidConfig`); `.leeway(Duration)` (padrao zero).
   - `TokenIssuer::new(access: SigningKey, refresh: SigningKey, TokenIssuerSettings) -> Result<Self, JwtError>`.
   - `AuthConfig::new(VerifyingKeySet, issuer, audience) -> Result<Self, JwtError>`; `.leeway(Duration)`.
7. **Variantes novas alem do design** (necessarias para nao esconder falhas): `JwtError::{InvalidConfig, UnsupportedAlgorithm, InvalidClaims}`; `KeyError` com `InvalidPem`, `NotPkcs8`/`NotSpki`, `NotEcP256`, `DuplicateKid`, `EmptyKid`, `Io`, `Source`. Claim obrigatoria ausente (`exp`, `sub`) -> `Malformed`; `iss`/`aud` ausentes -> `WrongIssuer`/`WrongAudience`; `token_type` ausente ou diferente -> `WrongTokenType`.
8. **`VerifyingKeySet::new(Vec<VerifyingKey>) -> Result<Self, KeyError>`** (desvio do design `-> Self`): `kid` duplicado e erro; silenciar sobrescrita seria perigoso. Existe `SigningKey::verifying_key() -> VerifyingKey` (necessario para o emissor publicar o JWKS).
9. **`TokenType` no JWT:** claim `token_type` com valores `"access"` / `"refresh"` (serde `rename_all = "lowercase"`).
10. **`Authenticated<C>` reaproveita** o `VerifiedJwt<C>` colocado nas extensoes pelo `RequireClaims<C>` (exige `C: Clone + Send + Sync + 'static`); se nao houver, verifica ele mesmo.
11. **Erro HTTP do Axum:** 401 -> `DerustError::without_body(UNAUTHORIZED, "unauthorized", tags)` com header `WWW-Authenticate: Bearer`; 403 -> `without_body(FORBIDDEN, "forbidden", ...)`; 500 (extensao ausente) -> `without_body(INTERNAL_SERVER_ERROR, "auth not configured", ...)` + `tracing::error!` explicando "aplique AuthConfig::layer() depois dos route_layer". O corpo e generico; o motivo (nome da variante de `JwtError`, nunca o token) vai em `DerustTags` (`auth_failure`) para o log do middleware.
12. **Limites defensivos internos:** JWT/JWE maiores que 16 KiB (constante `MAX_TOKEN_LEN`) -> `Malformed`; JWE com `zip`, `crit`, `epk` nao P-256, `encrypted_key` nao vazio -> recusado; JWT com `crit`, `jwk`, `jku`, `x5u`, `x5c` no header -> `Malformed`.

## Task T3: JWT (`TokenType`, `JwtSigner`, `JwtVerifier`, `VerifiedJwt`)

**Dificuldade:** complexa. **Depende de:** T2. **Paralelo com:** T5, T6. **Bloqueia:** T4, T8, T7.

**Files:** `cryptox/jwt.rs`, `cryptox/jose.rs` (funcoes JWS), `mod.rs`.

**API:**
```rust
#[derive(Clone, Copy, Debug, PartialEq, Eq, Serialize, Deserialize)] #[serde(rename_all="lowercase")]
pub enum TokenType { Access, Refresh }
pub struct JwtSignerSettings { pub issuer: String, pub audience: String, pub ttl: Duration }
JwtSigner::new(SigningKey, TokenType, JwtSignerSettings) -> Result<Self, JwtError>
JwtSigner::sign<C: Serialize>(&self, subject: impl Into<String>, claims: C) -> Result<String, JwtError>
JwtSigner::sign_at<C: Serialize>(&self, now: SystemTime, subject, claims) -> Result<String, JwtError>
JwtVerifier::new(VerifyingKeySet, TokenType, issuer, audience) -> Result<Self, JwtError>
JwtVerifier::leeway(self, Duration) -> Self                          // padrao zero
JwtVerifier::verify<C: DeserializeOwned>(&self, jwt: &str) -> Result<VerifiedJwt<C>, JwtError>
JwtVerifier::verify_at<C: DeserializeOwned>(&self, jwt: &str, now: SystemTime) -> Result<VerifiedJwt<C>, JwtError>
VerifiedJwt<C>: subject() -> &str, claims() -> &C, into_claims() -> C, expires_at(), issued_at() -> SystemTime,
                jti() -> &str, kid() -> &str, token_type() -> TokenType     // #[derive(Clone)] quando C: Clone
```

**Contexto e regras (cada uma tem teste):**

*Assinatura:* header `{"alg":"ES256","typ":"JWT","kid":<kid>}`; payload = claims do usuario (objeto JSON; `()`/`null` = vazio; outro tipo -> `InvalidClaims`) + `iss`, `aud` (string), `sub`, `iat = now`, `nbf = now`, `exp = now + ttl`, `jti` (16 bytes aleatorios em hex), `token_type`. Claim do usuario com nome reservado (`iss aud sub exp nbf iat jti token_type`) -> `JwtError::ReservedClaim` **sem** sobrescrever. Tempo em segundos inteiros (NumericDate).

*Verificacao, nesta ordem exata (nao pular nem reordenar):*
1. tamanho <= `MAX_TOKEN_LEN`; 3 segmentos base64url sem padding; senao `Malformed`.

Todas as comparacoes de `iss`/`aud` sao exatas (sem normalizacao). Erros nunca incluem token nem claims.
